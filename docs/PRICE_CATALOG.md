## Request rules

Every rule is applied to the request as sent: `extra_body` fields count exactly like top-level ones.

- Anthropic `speed`: allowed `standard`. Fast mode (`speed: "fast"`, $8/$40 on Opus 5.5, $10/$50 on Opus 5 and 4.8) is refused before dispatch until a catalog certifies its rate card.
- Anthropic `inference_geo`: `global` x1, `us` x1.1 (1.1x on every token category for Claude 4.6 and later, applied to every model as a ceiling). Other values are refused.
- Endpoints: first-party hosts (anthropic: api.anthropic.com; openai: api.openai.com) bill at list. Any other host (OpenAI data-residency `<cc>.api.openai.com`, FedRAMP, Azure, Bedrock, Vertex, a proxy) is priced at x1.1. An operator may declare an exact host list-priced with `KAZENAI_ENDPOINT_PRICE_MULTIPLIERS='{"llm-proxy.internal": "1"}'`; values below 1, wildcards, and paths are refused.
- A reported tier other than the pin is settled on that tier's certified row times the same request multiplier, or held under the operator risk multiplier.

## Signed live catalog

- Format: `kazenai.price-catalog.v1` payload inside a `kazenai.price-catalog.signed.v1` envelope. The payload string is the exact canonical JSON that was signed (Ed25519, base64url).
- Keys: public keys are pinned in `kazenai/catalog_document.py` `TRUSTED_CATALOG_KEYS`; the private key stays offline. `KAZENAI_PRICING_CATALOG_PUBLIC_KEYS` can add (never replace) keys for self-hosted deployments.
- Refused: unsigned or tampered files, unknown keys, other algorithms, non-canonical payloads, versions older than the bundled snapshot or than any catalog already accepted (no rollback), expired catalogs, and catalogs issued in the future.
- Distribution: KazenAI publishes the signed catalog to a CDN; Agent FinOps fetches and stores it (`KAZENAI_PRICING_CATALOG_URL`) and serves it to SDK keys at `GET /v1/pricing/catalog`. SDKs connected to FinOps verify it themselves and cache it (`KAZENAI_PRICING_LIVE=0` turns this off). An SDK without FinOps uses the bundled snapshot.
- Authority: FinOps prices every reservation and settlement from its own catalog and keeps the higher of its figure and the SDK's, so a stale SDK cannot under-charge and an SDK on another catalog version is not refused.

## What the reserve decision carries

The decision freezes catalog version, presented and canonical ids, request tier, context band, rate vector (with any request multiplier folded in), rounding rule, and pricing source. Settlement uses that frozen vector. Settle bodies send the priced token components (`usage_evidence.tokens`) so FinOps can re-price them on the reservation's frozen card.
